# CLAUDE.md — rules for AI agents in this repo

## Read first

- `docs/README.md` — index of all project docs
- `docs/vision.md` — goals and principles
- `docs/roadmap.md` — milestones
- `docs/process/github-workflow.md` — labels, Definition of Done, branch and commit rules
- `docs/decisions/` — accepted decisions (ADRs). Do not go against an accepted ADR. Propose a new ADR instead.

## Hard rules

1. **One issue, one PR.** Put `Closes #NN` in the PR body.
2. **Engine is pure.** `packages/engine` has no React, no network, no vendor imports, no `Math.random` (dice come from an injected RNG).
3. **Vendors only in adapters.** Vendor SDKs (Convex, Better Auth, Sentry, PostHog, etc.) are imported only in `packages/adapters/*` and in the Convex functions in `apps/server`. Everything else uses interfaces from `packages/contracts`.
4. **Rules come from `docs/rules/`.** If code and the rules doc disagree, raise it in the issue. Every numbered edge case in a rules doc needs a unit test.
5. **Conventional Commits** (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`).
6. **Simple English** in docs and comments: short sentences, active voice.
7. Do not add secrets to the repo. Public client config uses `EXPO_PUBLIC_*` env vars only.

## When you finish a task

- Update the docs the change touches.
- If you learned something future agents need, add it here or to the right doc.

## Tooling notes

- Run `pnpm install`, `pnpm lint`, `pnpm typecheck` and `pnpm format:check` from the repo root. For tests run `pnpm test:changed` (changed packages and their dependents, plus the app's Jest tests related to changed app files; `git fetch origin main` first). CI runs the full `pnpm test` on every push, so do not run it before each push. Run the app's whole Jest (`pnpm --filter @tavli/mobile test`) when you change something many app tests use: engine rules, the bot, contracts, `apps/mobile/test/*` or `jest.setup.ts` (#287).
- pnpm is pinned in `package.json` (`packageManager`). pnpm switches to that version by itself. Corepack 0.34 cannot run pnpm 12, so do not rely on Corepack.
- ESLint stays on 9.x for now. `eslint-config-expo` 58 uses `eslint-plugin-react` 7.x, which crashes on ESLint 10.
- The lint config is one file: `eslint.config.mjs`. It blocks vendor SDKs (including `expo-haptics`, `expo-audio` and `expo-secure-store`) outside `packages/adapters/**` and `apps/server/**`, React/Expo in `engine`, `bot` and `contracts`, and `Math.random` in `engine`.
- CI (`.github/workflows/ci.yml`) runs `lint`, `typecheck`, `test` and `format:check` in parallel jobs; the last job, `checks`, is the required one and passes only when the others passed or were skipped (#248). The app's Jest runs in 2 shards (`apps/mobile/test/shardSequencer.js` splits by file size). Do not add `paths-ignore` to it: a skipped required check blocks the PR. See the CI section in `docs/process/github-workflow.md`.
- Two required checks: `checks` (`.github/workflows/ci.yml`) and `claude-review` (`.github/workflows/claude-review.yml`). `claude-review` runs `/code-review high` on each PR and fails on a blocking finding (see `docs/process/github-workflow.md`). Fix blocking findings before you ask the owner to merge.
- Analytics go through the `Analytics` port (`@tavli/analytics-posthog`). It drops every call until `optIn()`; the user's answer lives in `features/privacy/` (`consent.ts`, `consentStore.ts`), not in Settings. It is the one privacy switch: crash reports follow it too (`features/crash/consent.ts`). New events go in `AnalyticsEvents` (contracts) **and** `docs/architecture/analytics-events.md` (a test checks). Never send names, emails or setting values.
- The first-launch gate (language, then consent, then the board step) is in `apps/mobile/src/app/_layout.tsx` (`Stack.Protected` on the consent answer and the board step), not on Home. List every new route in its app group, or a deep link skips consent (`welcomeFlow.test.tsx` checks). An invite link on first launch opens the invite after the welcome flow: `usePendingInvite` (`features/invites/pendingInvite.ts`) keeps the code and sets the welcome group's `redirectTo` (#256). Raise `CONSENT_VERSION` (`features/privacy/consent.ts`) only when the consent text changes so much that users must answer again.
- The board step (#350, `/welcome/board`, `features/welcome/WelcomeBoardScreen.tsx`) reuses the Settings pickers and comes after the first consent answer. Its status (`new`, `due`, `done`) has its own storage key (`boardStep.ts`, `boardStepStore`): the consent screen calls `begin()` before it saves the first answer, Continue calls `finish()`. A saved consent answer with no saved step loads as `done`, so players who update never see it. Tests that set `consentStore` directly skip it (the store loads `new`, which is not due); a test that drives the welcome flow resets `boardStepStore` to `new` and taps Continue on the board step after the consent answer.
- Analytics calls from the game store go through `quietly()` (`apps/mobile/src/features/analytics/quietly.ts`): an analytics error must never fail or undo a move. The hint, the game review and the tutorial use it too; import it from there, not from the game store.
- `@tavli/contracts/testing` holds port contract checks. The analytics checks are plain functions, so Vitest and Jest can both run them.
- App tests that need navigation use `renderRouter` from `expo-router/testing-library`. Render it once per test: a second `renderRouter` in the same test leaves the next test with an empty tree.
- In Asodio a turn can keep the same player to move (extra rolls, the chosen double after a 1-2 in the Acey-Deucey presets). Code that drives turns (bot scoring, `simulate`, the app) must follow `state.toMove`, play `state.dice` when the state already holds dice, and never assume the players alternate.
- Analytics events: `ANALYTICS_EVENTS` in `packages/contracts/src/analytics.ts` is the one list. Send an event with `analytics.track('name', …)` and the name as a string literal: `apps/mobile/src/features/analytics/eventPlan.test.ts` reads the source and checks it. Update `docs/architecture/analytics-events.md` in the same PR.
- Gesture Handler 3: a pan only activates on a move, so a pan alone never sees a quick tap (it FAILS, `canceled: true`). The board races a pan and a tap (#174). The Worklets Babel plugin does not allow a spread (`...config`) in a gesture hook config: write each prop out. The Jest mock (`apps/mobile/test/gestureHandlerMock.tsx`) follows the native state machine; keep it that way, or tests pass while phones break. It knows nested `GestureDetector`s: `touch(id)` on an inner gesture also drives the gestures around it, and the first to activate cancels the others (the native default). Give every gesture a `testID`. Keep a tap gesture off buttons: an active gesture cancels a button press under it (`cancelsJSResponder`).
- Workspace packages export TypeScript source (`"main": "./src/index.ts"`). There is no build step. Metro and Vitest read the source.
- Never give two files in one folder names that differ only in case (for example `MoveList.tsx` and `moveList.ts`). A Mac's disk ignores case, so `tsc` there resolves the import to the wrong file and fails, while CI on Linux passes. `git ls-files | sed -E 's/\.(test\.)?(ts|tsx|js|jsx|mjs)$/.\1/' | sort -u | sort -f | uniq -di` lists clashes.
- `apps/server` holds the Convex functions (`convex/`). Its tests use `convex-test` in Vitest's `edge-runtime` environment and need no Convex account. `convex/_generated/` is committed. After you add or rename a file in `convex/`, run `pnpm --filter @tavli/server codegen`. It runs Convex's local backend once (no account, no keys; the first run downloads the backend binary), because the Better Auth component needs a push; `--system-udfs` no longer works (see "Codegen" in `docs/architecture/online-game-service.md`). A module path in `convex/` may only hold letters, digits, `_` and `.` (no `-`), or the push fails. Files with two dots (`*.test.ts`, `test.setup.ts`) are not deployed. Lint blocks `Math.random` and React there; dice use `createCryptoRng`. Every save schedules a turn-timer check (`checkTimeout`), so `games.test.ts` runs on fake timers (`vi.useFakeTimers()`, then `vi.advanceTimersByTime` + `t.finishInProgressScheduledFunctions()`). A Convex mutation that throws rolls back everything, so a call that must save something and still report an error returns the error as a value (`makeMove` → `TIMED_OUT`).
- Sign-in (#131): no public Convex function takes a player id. Each public one gets the caller from `signedInPlayer(ctx)` (`apps/server/convex/caller.ts`): the player id is `identity.subject` (the Better Auth user id), and no identity throws `NOT_SIGNED_IN`. A new public function must call it too. A call that saves the caller's id in a row uses `existingPlayer(ctx)` instead (#306): it also checks that the Better Auth user exists, since a token outlives its deleted user; its tests sign in as real users from `authUsers(t, n)` (`convex/test.setup.ts`, with `betterAuthTest.register(t)`). Server tests act as a player with `t.withIdentity({ subject })`; `auth.test.ts` registers the Better Auth component (`@convex-dev/better-auth/test`). `getGame` answers only the two players (a stranger gets `NOT_A_PLAYER`, a missing game `null`). The app side is the `AuthProvider` port (`@tavli/contracts`, contract checks `authProviderContract` in `@tavli/contracts/testing`) and its adapter `@tavli/auth-better-auth`. Keep `better-auth`, `@better-auth/expo` and `@convex-dev/better-auth` on the same versions in `apps/server` and the adapter.
- Sign-in keys (#397, ADR-0008): a guest saves the account with `AuthProvider.saveKey` and keeps the same id; a phone with no session uses `signInWithKey` (Better Auth's `/sign-in/social` with an Apple id token). Both need a nonce from `keyNonce()` (signed, 10 minutes, one use: `model/keyNonce.ts`, `usedKeyNonces`). Key changes go only through our `keyPlugin.ts` routes (`/key/save`, `/key/list`, `/key/remove`); `/link-social` and `/unlink-account` stay off (`DISABLED_PATHS` in `convex/auth.ts`). Every new key `account` row is claimed first in one mutation (`claimKey`, `authKeys` table, from `databaseHooks.account.create.before`), so one Apple id has one owner (a claim with no `account` row is stale after `CLAIM_GRACE_MS` and goes to the next claimer), and one user holds one key per provider (`claimKey` returns `provider-taken`); a new key provider joins `KEY_PROVIDER_IDS` and `AUTH_KEY_PROVIDERS`. Never turn on implicit linking by email or let a sign-in delete a guest (`disableDeleteAnonymousUser`). A guest whose key has an account already gets a move offer in the `KEY_BELONGS_TO_OTHER` body (#403): a signed ticket (`model/moveTicket.ts`) that `/key/move` takes to run `startGuestMove` (`convex/guestMove.ts`: one mutation, then paged jobs per table) and sign in to the account; the server never takes either id from the app. A new table or field with a player id must be moved there too, next to `deleteMyAccount`. The Convex JWT holds only `sub` and the session id (`definePayload`). Server tests use a fake Apple (`convex/test.apple.ts`: `useFakeApple(await fakeApple())`, `stopFakeApple()` in `afterEach`); never let a test reach Apple. `convex/betterAuthClient.test.ts` runs the auth contract on Better Auth's real client against the real routes (`phoneFetch`); a change to the adapter's calls or to a route must keep it passing. Import the adapter there from `@tavli/auth-better-auth/provider`: the package root loads `expo-secure-store`. The in-memory provider takes `memoryAppleIdToken(sub, nonce)`. Apple tokens (#398, `convex/appleTokens.ts`): `/key/apple-code` keeps Apple's refresh token, encrypted, in `appleTokens`; key removal and account delete revoke it through the `appleRevokes` queue (only the row id goes in scheduler args; never log a token, email or Apple id). A newer token replaces the old one with no revoke: a revoke ends the person's Sign in with Apple for the app. `POST /apple/notifications` drops a key on Apple's `consent-revoked` or `account-delete`, and the account with its last key. Tests swap Apple's token calls with `setAppleTokenClient(fake)` and `setAppleTokenClient(null)` in `afterEach`. See "Sign-in keys" and "Apple tokens and the revoke" in `docs/architecture/online-game-service.md`.
- Email code (#399, ADR-0008): our own routes in `keyPlugin.ts` (`/key/email-code`, `/key/email-sign-in`, and `/key/save` with `{ provider: 'email', email, code, ticket }`), never Better Auth's `emailOTP` plugin (it joins accounts by `user.email`). The key is an `account` row with provider `email` and the normalized address (`normalizeEmail`, `@tavli/contracts`), claimed by `claimKey` like Apple. `emailCodes` and `emailCodeSends` hold only HMACs; the send limits and the try count are one mutation each (`emailCodes.ts`, pure parts in `model/emailCode.ts`). Every code check needs the ticket that the send gave the asking phone (the adapter keeps it in memory; the port has none), so a stranger who knows the address cannot use up its tries; never check a code by the address alone. A known and a new address get the same answer (also a `Rejected` mail); the account lookup only picks the limits (an email key's address is never under the `EMAIL_CODES_PER_DAY` cap). A failed mail takes its send back (`cancelEmailCode`). `/key/email-sign-in` refuses a phone with a session (`SIGNED_IN`): a guest saves with `/key/save`. Mail goes through the `MailSender` port (contract `mailSenderContract`) and `@tavli/mail-ahasend` (`fetch` only), built in `convex/mail.ts` from env vars. Server tests call `setMailSender(createRecordingMailSender())` in `beforeEach` and `setMailSender(undefined)` in `afterEach`, and read the code from the recorded mail; never let a test reach AhaSend, and never log an address or a code. The contract subject's `emailCode(email)` reads the fake inbox. See "Email code" in `docs/architecture/online-game-service.md`. The app's step is `EmailCodeForm` (`features/online/`, #433), used by the sign-in choices (`withEmail`) and Settings → Account; never add a second code form. Screen tests drive it with `test/emailCode.ts` (`enterEmailCode(user, onlineFake.authStore, email)` reads the in-memory inbox). See "The email code step" in `docs/architecture/app-shell.md`.
- The Convex client adapter `@tavli/backend-convex` (#253) names the server functions itself (`GAME_FUNCTIONS` and, for its `Invites` adapter `createConvexInvites` (#281), `INVITE_FUNCTIONS` in `src/functions.ts`); it never imports `apps/server` (`apps/server` has it as a dev dependency, so that would be a cycle). When you change a public function in `games.ts` or `invites.ts`, change `functions.ts` too: `apps/server/convex/convexTransport.test.ts` and `convexInvites.test.ts` check names and types against `api`, and run `gameTransportContract()` / `invitesContract()` through the adapter on the real functions (fake clients in `convex/test.network.ts`). Keep `convex` on the same version in `apps/server` and both adapters.
- The online game model lives in `packages/online` (`@tavli/online`, pure, #251): `online-game.ts` (the model), `calls.ts` (the call checks: caller, version, deadline) and `memory-server.ts` (`createMemoryGameServer({ rng, now })`, a `GameTransport` per player). The Convex functions import it and keep only the database and scheduler parts; never copy a check into `games.ts`. The app must not import `apps/server`: use `@tavli/online`. The in-memory server runs no timers: call `runDueTimeouts()` after you move its `now`. The server stops at each roll (`awaiting-roll`, #355): a player rolls with `rollDice` (checked for caller, version and deadline; the roll keeps the turn's deadline, `rollDeadline`), and a roll with no legal move passes in the engine (`game.lastTurn` holds the pass and its dice). The opening of a new match waits too (#379): each player rolls their own die with `rollDice`, in any order, with no version check while the stored game is in `opening-roll` (`rollCallVersion`). There `waitingFor` names White until White's die is in, then Black: use `mayRollOpening(view, side)` to know who may roll. With no die by the deadline the server rolls both; with one die in, the other side loses on time. Only the next game of a match stays automatic. A test that needs a turn rolls both opening dice first: `openMemoryGame(server, gameId)` or `rollOpenings` (`@tavli/online/testing`), `openFlow(flow, rng)` on a flow, `openGame(t, gameId, players)` in `convex/test.setup.ts`, `onlineFake.openGame(gameId)` in the app. A new `GameTransport` call goes in the memory server, `games.ts` (through `save`), the Convex adapter, the contract checks and every `GameTransport` literal. Read a stored game once with `loadStored(text)` and save a step with `storeStep(loaded, next)` (the steps return a `SteppedFlow`), never `storeFlow(next, …)`, or the view loses the turn that ended a game (`previousGame`, #299). A `GameTransport` adapter runs `gameTransportContract()` from `@tavli/contracts/testing` (plain async checks; test helpers such as `pickTurn`, `motherPin` and `closedOut` are in `@tavli/online/testing`). Server tests roll real dice: a test that expects a side to move after a roll needs a position where every roll has a legal move, or it fails at random (#308: `motherPin` keeps White movable after `playOn`, and `testing.test.ts` checks all 36 rolls). A test of a pass uses `closedOut(flow, player)`: that side waits to roll and no roll can move (`testing.test.ts` checks all 36 rolls too). A test that needs a move rolls first, and rolls again after a pass.
- Invites (#252): `apps/server/convex/invites.ts` holds the Convex functions, `packages/online/src/invites.ts` the pure checks (`now` and the `Rng` are arguments, no Convex types; #256 moved them there for the in-memory server). The app answers invites through the `Invites` port (contracts); its contract checks are `invitesContract()` in `@tavli/contracts/testing`, and the in-memory server, the Convex functions and the Convex adapter all run them. Codes come from `createCryptoRng` too. Home lists the caller's open invites live with `watchMyInvites` (#314, the `listMyInvites` query through `onUpdate`); a row stays until the server list drops it (the scheduled `expireInvite` patches the row, so the query runs again), and the phone clock only gives the time left ("Expiring now"), so a wrong phone clock never hides an open invite. A game between two people starts only from `acceptInvite`; `createGame` is an `internalMutation` (#274: tests call it with `t.mutation(internal.games.createGame, { callerId, … })`). Both start a game through one helper, `insertGame` in `games.ts`: never copy the game creation, and never make a public function that starts a game without the other player's consent. An open invite counts as expired at `expiresAt` also before the scheduled `expireInvite` runs. One player may have at most `MAX_OPEN_INVITES` (10) open invites (#275): both servers check it with `countOpenInvites` + `checkInviteCap` from `@tavli/online` (Convex reads the `by_from` index range `expiresAt > now`), before they pick a code.
- Account deletion (#302): `deleteMyAccount` (`apps/server/convex/account.ts`) resigns the caller's active games through `resignAs` (the save path of `resign`) in pages of `GAME_RESIGN_PAGE`: the first page in the call, the rest in the scheduled `resignActiveGames` (#309; active games have no cap), keeps finished games (the id stays; our tables hold no name), deletes the caller's open invites and push tokens, then the Better Auth user with `internalAdapter.deleteUser` (`createAuth(ctx).$context`), then schedules `deleteSentInvites` for the other invites in pages (a transaction writes at most 16,000 documents, #306). Never `.collect()` a table there that has no cap. It deletes the caller's key claims (`deleteKeysOf`, #397) and name row (`deletePlayerNameOf`: guest number, username, terms and age record; #400, #405) too, and moves the caller's Apple tokens to the revoke queue (`revokeAppleTokensOf`, #398); the body is `deleteAccountOf(ctx, userId)`, which Apple's notice route also runs. A new table or field that holds a player's data must be handled there too, and in the guest move (`guestMove.ts`, #403). Better Auth's delete routes stay off (`disabledPaths` in `convex/auth.ts`), so no client skips those steps. A token outlives its user, so the call checks the user exists (`existingPlayer`, `NOT_SIGNED_IN`). Its tests sign in real guests over HTTP (`betterAuthTest.register`). The app calls it **Delete my account** in Settings → Account (#402; a guest sees **Delete my guest account**): the `OnlineData` port (`createConvexOnlineData`, `ACCOUNT_FUNCTIONS` in `backend-convex`, `onlineDataFor` on the memory server), run by `deleteOnlineData` (`features/online/deleteData.ts`) through `signOutOfOnline(auth, pushes, before)` (token, delete, sign-out, note); `NOT_SIGNED_IN` from the delete counts as done.
- Settings → Account (#402, `/account`, `features/account/`: `useAccount.ts`, `AccountScreen.tsx`): offline (no `hasOnlineAccount()` or no session; no server call), guest (`MyUsername.guestNumber`, Save my account with Apple through `saveKey`) or saved (username, keys, Sign out, delete). - Push (#280): the port is `PushProvider` (`packages/contracts/src/push.ts`, contract checks `pushProviderContract` in `@tavli/contracts/testing`, `createRecordingPushProvider` for tests). The Expo sender is `@tavli/push-expo` (`fetch` only, batches of 100, a 10 s time limit per request, `isExpoPushToken`). `apps/server/convex/push.ts` holds the `pushTokens` table's functions (`registerPushToken` via `existingPlayer`, `removePushToken` via `signedInPlayer`), `scheduleTurnPush` and the action `sendTurnPush`; the pure parts (who gets a push, the text `TURN_PUSH_TEXT`, the cap of 5) are in `convex/model/push.ts`. Every save in `games.ts` (`save`, `insertGame`) calls `scheduleTurnPush` with what the server waited for before and after (`turnWait`: side, game number and `over`) and the caller: a new save path must too. A push goes out only in an async game, never to the caller, and only when the wait moves to the other side or a new game of the match starts. The save that ends an async match sends "game over" instead (`matchEndPushSides`, `MATCH_END_PUSH_TEXT`, #316): to the other player, or to both after a time out; the same `sendTurnPush` with `kind: 'matchEnd'`. Turn pushes are `priority: 'high'` with a ttl up to the turn deadline (`turnPushTtl`). A `Failed` or `MessageRateExceeded` push is sent once more after 30 s (`sendTurnPush` `attempt`); `fail(token)` on the recording provider tests it. Server tests swap the sender with `setPushProvider(createRecordingPushProvider())` in `beforeEach` and `setPushProvider(null)` in `afterEach`; never let a test reach Expo. The push runs as a scheduled action: `vi.advanceTimersByTime(0)` + `t.finishInProgressScheduledFunctions()` runs it.

- Deploys (#257): `.github/workflows/deploy-server.yml` deploys `apps/server` to the Convex dev deployment on each `main` push (paths filter) and to prod only by hand (target `prod`, from `main`, environment `production`). - The Asodio heuristic has a golden test (#225): `packages/bot/src/evaluators/asodio-heuristic.golden.json` holds its exact scores on 2,100 seeded positions. A speed change must keep them all.
