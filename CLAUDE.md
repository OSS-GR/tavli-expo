# CLAUDE.md — rules for AI agents in this repo

## Read first

- `docs/README.md` — index of all project docs
- `docs/vision.md` — goals and principles
- `docs/roadmap.md` — milestones
- `docs/process/github-workflow.md` — labels, Definition of Done, branch and commit rules
- `docs/decisions/` — accepted decisions (ADRs). Do not go against an accepted ADR. Propose a new ADR instead.

## Hard rules

1. **One issue, one PR.** Put `Closes #NN` in the PR body.
2. **Engine is pure.** `packages/engine` has no React, no network, no vendor imports, no `Math.random` (dice come from an injected RNG).
3. **Vendors only in adapters.** Vendor SDKs (Convex, Better Auth, Sentry, PostHog, etc.) are imported only in `packages/adapters/*` and in the Convex functions in `apps/server`. Everything else uses interfaces from `packages/contracts`.
4. **Rules come from `docs/rules/`.** If code and the rules doc disagree, raise it in the issue. Every numbered edge case in a rules doc needs a unit test.
5. **Conventional Commits** (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`).
6. **Simple English** in docs and comments: short sentences, active voice.
7. Do not add secrets to the repo. Public client config uses `EXPO_PUBLIC_*` env vars only.

## When you finish a task

- Update the docs the change touches.
- If you learned something future agents need, add it here or to the right doc.

## Tooling notes

- Run `pnpm install`, `pnpm lint`, `pnpm typecheck` and `pnpm test` from the repo root.
- pnpm is pinned in `package.json` (`packageManager`). pnpm switches to that version by itself. Corepack 0.34 cannot run pnpm 12, so do not rely on Corepack.
- ESLint stays on 9.x for now. `eslint-config-expo` 58 uses `eslint-plugin-react` 7.x, which crashes on ESLint 10.
- The lint config is one file: `eslint.config.mjs`. It blocks vendor SDKs (including `expo-haptics`, `expo-audio` and `expo-secure-store`) outside `packages/adapters/**` and `apps/server/**`, React/Expo in `engine`, `bot` and `contracts`, and `Math.random` in `engine`.
- CI (`.github/workflows/ci.yml`) runs `lint`, `typecheck`, `test` and `format:check` in parallel jobs; the last job, `checks`, is the required one and passes only when the others passed or were skipped (#248). The app's Jest runs in 2 shards (`apps/mobile/test/shardSequencer.js` splits by file size). Do not add `paths-ignore` to it: a skipped required check blocks the PR. See the CI section in `docs/process/github-workflow.md`.
- Two required checks: `checks` (`.github/workflows/ci.yml`) and `claude-review` (`.github/workflows/claude-review.yml`). `claude-review` runs `/code-review high` on each PR and fails on a blocking finding (see `docs/process/github-workflow.md`). Fix blocking findings before you ask the owner to merge.
- Analytics go through the `Analytics` port (`@tavli/analytics-posthog`). It drops every call until `optIn()`; the user's answer lives in `features/privacy/` (`consent.ts`, `consentStore.ts`), not in Settings. It is the one privacy switch: crash reports follow it too (`features/crash/consent.ts`). New events go in `AnalyticsEvents` (contracts) **and** `docs/architecture/analytics-events.md` (a test checks). Never send names, emails or setting values.
- The first-launch gate (language, then consent) is in `apps/mobile/src/app/_layout.tsx` (`Stack.Protected` on the consent answer), not on Home. List every new route in its app group, or a deep link skips consent (`welcomeFlow.test.tsx` checks). An invite link on first launch opens the invite after consent: `usePendingInvite` (`features/invites/pendingInvite.ts`) keeps the code and sets the welcome group's `redirectTo` (#256). Raise `CONSENT_VERSION` (`features/privacy/consent.ts`) only when the consent text changes so much that users must answer again.
- Analytics calls from the game store go through `quietly()` (`apps/mobile/src/features/analytics/quietly.ts`): an analytics error must never fail or undo a move. The hint, the game review and the tutorial use it too; import it from there, not from the game store.
- `@tavli/contracts/testing` holds port contract checks. The analytics checks are plain functions, so Vitest and Jest can both run them.
- App tests that need navigation use `renderRouter` from `expo-router/testing-library`. Render it once per test: a second `renderRouter` in the same test leaves the next test with an empty tree.
- In Asodio a turn can keep the same player to move (extra rolls, the chosen double after a 1-2 in the Acey-Deucey presets). Code that drives turns (bot scoring, `simulate`, the app) must follow `state.toMove`, play `state.dice` when the state already holds dice, and never assume the players alternate.
- Analytics events: `ANALYTICS_EVENTS` in `packages/contracts/src/analytics.ts` is the one list. Send an event with `analytics.track('name', …)` and the name as a string literal: `apps/mobile/src/features/analytics/eventPlan.test.ts` reads the source and checks it. Update `docs/architecture/analytics-events.md` in the same PR.
- Gesture Handler 3: a pan only activates on a move, so a pan alone never sees a quick tap (it FAILS, `canceled: true`). The board races a pan and a tap (#174). The Worklets Babel plugin does not allow a spread (`...config`) in a gesture hook config: write each prop out. The Jest mock (`apps/mobile/test/gestureHandlerMock.tsx`) follows the native state machine; keep it that way, or tests pass while phones break.
- Workspace packages export TypeScript source (`"main": "./src/index.ts"`). There is no build step. Metro and Vitest read the source.
- `apps/server` holds the Convex functions (`convex/`). Its tests use `convex-test` in Vitest's `edge-runtime` environment and need no Convex account. `convex/_generated/` is committed. After you add or rename a file in `convex/`, run `pnpm --filter @tavli/server codegen`. It runs Convex's local backend once (no account, no keys; the first run downloads the backend binary), because the Better Auth component needs a push; `--system-udfs` no longer works (see "Codegen" in `docs/architecture/online-game-service.md`). A module path in `convex/` may only hold letters, digits, `_` and `.` (no `-`), or the push fails. Files with two dots (`*.test.ts`, `test.setup.ts`) are not deployed. Lint blocks `Math.random` and React there; dice use `createCryptoRng`. Every save schedules a turn-timer check (`checkTimeout`), so `games.test.ts` runs on fake timers (`vi.useFakeTimers()`, then `vi.advanceTimersByTime` + `t.finishInProgressScheduledFunctions()`). A Convex mutation that throws rolls back everything, so a call that must save something and still report an error returns the error as a value (`makeMove` → `TIMED_OUT`).
- Sign-in (#131): no public Convex function takes a player id. Each public one gets the caller from `signedInPlayer(ctx)` (`apps/server/convex/caller.ts`): the player id is `identity.subject` (the Better Auth user id), and no identity throws `NOT_SIGNED_IN`. A new public function must call it too. Server tests act as a player with `t.withIdentity({ subject })`; `auth.test.ts` registers the Better Auth component (`@convex-dev/better-auth/test`). `getGame` answers only the two players (a stranger gets `NOT_A_PLAYER`, a missing game `null`). The app side is the `AuthProvider` port (`@tavli/contracts`, contract checks `authProviderContract` in `@tavli/contracts/testing`) and its adapter `@tavli/auth-better-auth`. Keep `better-auth`, `@better-auth/expo` and `@convex-dev/better-auth` on the same versions in `apps/server` and the adapter.
- The Convex client adapter `@tavli/backend-convex` (#253) names the server functions itself (`GAME_FUNCTIONS` in `src/functions.ts`); it never imports `apps/server` (`apps/server` has it as a dev dependency, so that would be a cycle). When you change a public function in `games.ts`, change `functions.ts` too: `apps/server/convex/convexTransport.test.ts` checks names and types against `api`, and runs `gameTransportContract()` through the adapter on the real functions. Keep `convex` on the same version in `apps/server` and both adapters.
- The online game model lives in `packages/online` (`@tavli/online`, pure, #251): `online-game.ts` (the model), `calls.ts` (the call checks: caller, version, deadline) and `memory-server.ts` (`createMemoryGameServer({ rng, now })`, a `GameTransport` per player). The Convex functions import it and keep only the database and scheduler parts; never copy a check into `games.ts`. The app must not import `apps/server`: use `@tavli/online`. The in-memory server runs no timers: call `runDueTimeouts()` after you move its `now`. A `GameTransport` adapter runs `gameTransportContract()` from `@tavli/contracts/testing` (plain async checks; test helpers such as `pickTurn` and `motherPin` are in `@tavli/online/testing`).
- Invites (#252): `apps/server/convex/invites.ts` holds the Convex functions, `packages/online/src/invites.ts` the pure checks (`now` and the `Rng` are arguments, no Convex types; #256 moved them there for the in-memory server). The app answers invites through the `Invites` port (contracts); its contract checks are `invitesContract()` in `@tavli/contracts/testing`, and the in-memory server and the Convex functions both run them. Codes come from `createCryptoRng` too. A game between two people starts only from `acceptInvite`; `createGame` is an `internalMutation` (#274: tests call it with `t.mutation(internal.games.createGame, { callerId, … })`). Both start a game through one helper, `insertGame` in `games.ts`: never copy the game creation, and never make a public function that starts a game without the other player's consent. An open invite counts as expired at `expiresAt` also before the scheduled `expireInvite` runs.
- Push (#280): the port is `PushProvider` (`packages/contracts/src/push.ts`, contract checks `pushProviderContract` in `@tavli/contracts/testing`, `createRecordingPushProvider` for tests). The Expo sender is `@tavli/push-expo` (`fetch` only, batches of 100, `isExpoPushToken`). `apps/server/convex/push.ts` holds the `pushTokens` table's functions (`registerPushToken`, `removePushToken`, both via `signedInPlayer`), `scheduleTurnPush` and the action `sendTurnPush`; the pure parts (who gets a push, the text `TURN_PUSH_TEXT`, the cap of 5) are in `convex/model/push.ts`. Every save in `games.ts` (`save`, `insertGame`) calls `scheduleTurnPush` with what the server waited for before and after (`turnWait`: side and game number) and the caller: a new save path must too. A push goes out only in an async game, never to the caller, and only when the wait moves to the other side or a new game of the match starts. A `Failed` or `MessageRateExceeded` push is sent once more after 30 s (`sendTurnPush` `attempt`); `fail(token)` on the recording provider tests it. Server tests swap the sender with `setPushProvider(createRecordingPushProvider())` in `beforeEach` and `setPushProvider(null)` in `afterEach`; never let a test reach Expo. The push runs as a scheduled action: `vi.advanceTimersByTime(0)` + `t.finishInProgressScheduledFunctions()` runs it.
- Deploys (#257): `.github/workflows/deploy-server.yml` deploys `apps/server` to the Convex dev deployment on each `main` push (paths filter) and to prod only by hand (target `prod`, from `main`, environment `production`). Never give it a `pull_request` trigger: PR code must never see the deploy keys. When the functions import a new package, add its path to the filter. `convex/tsconfig.json` is what `convex deploy --typecheck enable` checks. The app reads the Convex URLs only through `apps/mobile/src/convexUrl.ts` (`convexServer()`); `app.config.ts` sets `extra.convexUrl` per variant (dev for `development`, prod for `preview` and `production`), and `EXPO_PUBLIC_CONVEX_URL` wins.
- pnpm build scripts: `esbuild` (from `convex`) is listed as `false` in `pnpm-workspace.yaml` `allowBuilds`. A new dependency with a build script fails `pnpm install` until you list it there.
- pnpm refuses packages published less than 24 hours ago (`minimumReleaseAge`). Pick the previous version. Do not add an exclusion.
- When Expo ships a patch less than 24 hours old, CI's `expo install --check` fails, but pnpm cannot install it yet. List those packages in `expo.install.exclude` in `apps/mobile/package.json` for one day, and open an issue to bump them and remove the list (#167).
- The Asodio heuristic has a golden test (#225): `packages/bot/src/evaluators/asodio-heuristic.golden.json` holds its exact scores on 2,100 seeded positions. A speed change must keep them all. Write the fixture again (`pnpm --filter @tavli/bot golden:asodio`) only when a change of the scores is the point. `pnpm --filter @tavli/bot bench:asodio` times it. The shot count (`asodio-shots.ts`) keeps one shared work space (`ShotSearch`) and plays moves in place with `playOne`/`undoOne`: every move it plays must be taken back. `asodio-shots.test.ts` compares it with the first version (`src/testing/asodio-shots-reference.ts`, never change that file), and checks that `lowestFrom` skips only points `canMove` refuses: change both when a move rule changes.
- Hint depth and budget (`hintPlies`, `hintRankOptions`, #219, #233, #237): every preset hints at 2 ply with its work budget (`TWO_PLY_HINT_BUDGETS` in `packages/bot/src/analyzer.ts`, in positions scored, never time). A preset's budget keeps its worst hint no slower than Plakoto's. Measure with `pnpm --filter @tavli/bot bench:hint` (500 seeded positions per game, `packages/bot/src/testing/hint-work.ts`; try more than one `--seed=`: the slow positions are rare; `--compare` counts the hints the budget cut). The numbers live in one place: "2-ply budget" in `packages/bot/README.md`; elsewhere link to it.
- Pure packages test with Vitest. The app tests with Jest (`jest-expo` + React Native Testing Library 14, where `render` and events are `async`). `apps/mobile/jest.setup.ts` loads the Unistyles mocks first, then swaps `@/services` for in-memory fakes and fixes the phone language to English.
- Tests that render the game screen run on fake timers (`GameScreen.*`, `MatchScreen`, `navigation`, `textScaling`): call `runOnFakeTimers()` from `apps/mobile/test/clock.ts` at the top of the file, and use its `setupUser()` instead of `userEvent.setup()`. The screen closes cards on timers (opening result 3 s, the Roll wait after an opening tie, pass card, bot answer note, match end), and the bot waits on timers. On a real clock a busy machine closes a card before the test taps it, and the test fails at random (#152). Move time with `jest.advanceTimersByTime` inside `act`; `waitFor` moves the fake clock by itself. Each tap of `setupUser()` moves the clock 130 ms. After an opening tie the Roll button waits `OPENING_TIE_WAIT_MS` (#176); a test that plays whole games with `fireEvent` presses it with `pressOpeningRoll()` (`apps/mobile/test/openingRoll.ts`), or a seed that ties loops forever.
- Never wait on the real clock in a test, for example `await new Promise((r) => setTimeout(r, ms))`, or `waitFor` on real timers for a card or a bot delay. When a test checks a delay, move the fake clock by that delay and check before and after (#160).
- `renderRouter` turns on fake timers by itself and never turns them off. A file that uses it and needs timers calls `runOnFakeTimers()` too, so every test starts and ends on a known clock. `runOnFakeTimers()` also works inside one `describe`, and it unmounts the screen before it switches back to real timers: a `renderRouter` tree unmounted on the real clock never stops (the test passes, then Jest hangs at 100% CPU, #159).
- Jest runs the React Compiler, like the app (`apps/mobile/jest.config.js` sets `supportsReactCompiler` for babel-preset-expo). Without it, tests that play a whole game are about three times slower. `jest.setup.ts` also swaps React Native's `jest.fn` `performance.now` for a plain function: a mock keeps every call, and React calls it on every render.
- Adapters are picked in one file: `apps/mobile/src/services.ts` (ADR-0002). `react-native-mmkv` is on the vendor list, so only `packages/adapters/storage-mmkv` may import it.
- Online play (#266): `services.ts` exports `auth` (`AuthProvider`) and `games` (`GameTransport`). Both are `undefined` when the build has no Convex URL (`convexServer()` in `apps/mobile/src/convexUrl.ts`); a screen checks `games === undefined` to show that online play is off. Both are built on first use (`apps/mobile/src/onlineServices.ts`), so the app makes no network call at start. Only `auth.signInAsGuest()` makes an account: call it when the user opens online play, never at launch. Never send the user id to analytics. The sign-in base URL is the site URL (`extra.convexSiteUrl`, the `.convex.site` twin of `extra.convexUrl`; `EXPO_PUBLIC_CONVEX_SITE_URL` wins). The game routes pick the server with `useOnlineConnection(id)` (`features/online/connection.ts`): a dev game (`isDevGame`, `devGameIds.ts`, #255) stays on the in-memory `onlineServer()` as `onlinePlayerId`; any other id plays on `games` as the user of the saved session (`auth.ready()`), and the route makes no guest (the invite screen, #256, will). Never call `gameTransportFor` for a non-dev game. Invites (#256) still live on the in-memory server: the invite route records an accepted game with `rememberDevGame`, so it opens there. In Jest, `auth`, `games`, `onlineServer()`, `gameTransportFor` and `invitesFor` share one in-memory sign-in and server (`apps/mobile/test/onlineFake.ts`, reset before each test with the dev ids); `games` acts as the user signed in to `auth`. The first PR whose screen makes a guest for a user to see updates the privacy policy (see `docs/legal/README.md`).

New adapters of a port with a shared contract test (`@tavli/contracts/testing`, Vitest only) must run it. Build tooling (`apps/mobile/metro.config.js`, `app.config.ts`) may use Sentry's build helpers directly.

- Styling is Unistyles 3. Its Babel plugin processes `apps/mobile/src` only. `apps/mobile/index.ts` configures Unistyles before Expo Router loads. Metro warns "invalid package.json configuration" for `react-native-unistyles/components/native/*`; it is harmless.
- ESLint does not resolve the `@/` alias (`import/no-unresolved` ignores it). `tsc` checks those imports.

Never add a rule check there. `InteractiveBoard` lights them only with `paths` and `onSteps` (the tutorial passes neither). One Undo takes a combined move back whole through `features/game/moveGroups.ts`; the engine still sees single moves.

Route tests live in `apps/mobile/src/navigation.test.tsx` and use `renderRouter('./src/app')`. That file mocks `expo-router/build/testing-library/mocks`, because the library's own Reanimated mock replaces ours.
- The app config is `apps/mobile/app.json` (base) plus `app.config.ts` (app variants by `APP_VARIANT`; default `development` = `com.tavlaki.dev`). Only `APP_VARIANT=production` uses `com.tavlaki`. - We use CNG: `apps/mobile/ios` and `android` are generated and ignored. Never commit them. Build profiles live in `apps/mobile/eas.json`; how to run the app is in `docs/process/running-the-app.md`.
- The tutorial (`apps/mobile/src/features/tutorial/`, #128) plays fixed positions with fixed dice and only filters the engine's legal moves per lesson (`lessonMoves`). Never add a rule check there. Lesson sets are per game (`LESSON_SETS`: Portes, Plakoto, Fevga, #149; Asodio, #159); each lesson plays in its game's default preset (`lessonRules`, from `DEFAULT_PRESET_BY_GAME`), and lesson ids are unique over all games (they name the strings and the analytics). The Portes status keeps the storage key `tutorial`; the others use `tutorial.<game>`. A new lesson set needs `TutorialGame` (contracts), `TUTORIAL_GAMES` (`features/match/routes.ts`, also the Settings picker), the `variants` of `progress.ts`, and the privacy policy's game list. `apps/mobile/test/tutorialTaps.ts` plays a lesson with taps in screen tests (`playLessonByTaps(index, game)`).
- A Skia canvas must keep its native parent: on iOS a canvas that moves loses its drawing (#173). A `View` that turns `accessibilityElementsHidden`, `importantForAccessibility`, `pointerEvents`, `opacity` and the like on and off needs `collapsable={false}`, or React Native moves its children between native views. `apps/mobile/test/nativeParent.ts` checks this in Jest.
- Only the game and tutorial routes turn with the phone (#185): the `orientation` options in `apps/mobile/src/app/_layout.tsx` (`app.json` allows every orientation). A new route stays upright. Those two screens pick their layout from the window (`useScreenLayout`, `features/board/screenLayout.ts`) and keep the board at the same place in the React tree in every layout, so turning the phone never remounts the board, the dice or a card. Anything placed from the measured board (the dice) waits for a geometry measured for the current `spaceKey`; never draw a child outside its parent (Android may clip it). A `Sheet` over them needs `turns` (iOS `Modal` orientations). `apps/mobile/test/window.ts` turns the phone in Jest (`setWindow`, then `resetWindow` in `afterEach`).
- Screen reader users play through the move list (`apps/mobile/src/features/accessibility/`, #134), not the Skia board. A new board action needs a button there too. Announce game events with `useAnnouncement` (both platforms), not `accessibilityLiveRegion` (Android only), and check `features/game/announcements.ts` first so nothing is read twice. A keyed event is read once per app run (#216), so the key must name the event for the whole run: put the game store's `matchKey` in it. `apps/mobile/test/afterEnv.ts` resets that store before each test. Text must not get `numberOfLines` or a fixed-height box: `textScaling.test.tsx` checks Home, New game, the game screen, the end screens, History and the tutorial mother card.
- React Native Testing Library skips views hidden from screen readers (`importantForAccessibility="no-hide-descendants"`, e.g. the win `Celebration`). Pass `{ includeHiddenElements: true }` to find them. The game screen hides the board while a card covers it, and the whole screen under the game-end sheet, the menu and the resign dialogs (#153), so a test that lays out `game-board` or reads the board label under a card needs it too.
- A new card or sheet over the board must hide what it covers from screen readers, move focus to its title (`useFocusOnShow`, `features/accessibility/focus.ts`) and scroll with a large font (see `GameScreen.tsx`, #153).
- Board themes live in `packages/themes` (one folder each, built by `pnpm --filter @tavli/themes build:assets -- <id>`, which needs Playwright Chromium). The board choice is the `boardTheme` setting, separate from `theme` (app colors). A new theme also needs `exports` in `packages/themes/package.json`, its images in `apps/mobile/src/features/board/themeImages.ts` and its sounds in `apps/mobile/src/features/feedback/themeSounds.ts`. Every theme shares the Walnut Kafeneio geometry (`themes.test.ts` checks it); new art imports it and the SVG helpers in `packages/themes/tools/lib/svg.mjs`. After a change to shared tool code, run `build:assets` for all themes and check that the other themes' images did not change.
- The game review (#215) lives in `apps/mobile/src/features/review/`. It replays the match log of the session in memory and ranks each person's turn with the `analyzer` from `@/services` (Jest uses the real one). It saves nothing: never put review data in the save slot or the history. Its thresholds and bands are in `review.ts` and `docs/architecture/board-screen.md` ("Game review"). Tests build scripted games with `apps/mobile/test/reviewGame.ts`; the review runs on timers, so use `findBy…` (it moves the fake clock).
- Match history (#142) lives in `apps/mobile/src/features/history/`. `sessions.ts` adds a record when a match is over or is replaced after it started (`history` dep). Do not put history in the save slot (`savedMatch.ts`). Tests that finish matches through `matchSessions` add records to the shared `historyStore`; clear it in `beforeEach` when a test counts them. A match is named by session id + `matchNumber` (+1 per rematch), in the save slot and in each record. `peek()` hides a save whose match the history already holds (#150) but never deletes it; only `start()` and `end(id)` delete. Never decide staleness by comparing times: the phone clock can move back. Shared UI pieces such as `ConfirmDialog` live in `apps/mobile/src/components/`, not in a feature.
- House rules on New game (#207, #241, parts of Kafeneio mode #58): `MatchSetup.openingRoll` and `MatchSetup.rulesVersions` (the preset of Plakoto and Asodio, one per game) go into the match rules through `gameRuleSet(game, openingRoll, rulesVersions)` (`features/match/setup.ts`). A preset id has a dot, so its text keys go through `VERSION_KEYS`. A Tavli match plays `rulesVersions.plakoto` in its Plakoto game (#247): its match preset is then that version with the Tavli rotation, and the engine's `gameRules` gives Portes and Fevga their defaults. So `match.rules.presetId` of a Tavli match is not always `tavli`; use `versionedGameOf` / `versionsOfPreset`, not `isVersionedGame(setup.game)`. Acey-Deucey American scores `perChecker`: `winType`, `isDiplo` and the analytics `resultKind` take the scoring method. The save slot drops a save whose setup and log rules differ. A new house rule needs: the field in `MatchSetup` and `sanitizeSetup` (old saves and last choices have none: use the default), `gameRuleSet`, the check in `parseSavedMatch`, the history record (`records.ts`, read from `match.rules`), a value id on `game_started`, and screen handling that only sends engine actions.
- Online games in the app (#254): `apps/mobile/src/features/online/onlineStore.ts` plays one game over the `GameTransport` port (see "Online games" in `docs/architecture/app-shell.md`). Each newer view replaces the local flow; moves and Undo stay on the phone, and Confirm sends the whole turn. Follow the view (`waitingFor`, `prompt`), never assume turns alternate. Its tests use `createMemoryGameServer` from `@tavli/online` with one store per player: the server runs no timers, so move its `now` and call `runDueTimeouts()`, and let its microtasks run (`flush()`), never the real clock.
- Hint depth (#219, #237): `hintPlies(rules)` in `apps/mobile/src/features/hint/hint.ts` picks the Analyzer's `plies` per rules preset (2 for every preset now), and `hintRankOptions(rules)` adds the preset's `budget`. A new preset must get an entry in both tables (the types check them). The game review stays at 1 ply. `packages/bot/src/analyzer-work.test.ts` checks that one hint never scores more than its budget (+1).
